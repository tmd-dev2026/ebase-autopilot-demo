# eBase Autopilot 体験版

出品の準備から在庫監視、注文、返信、収益の確認までを体験できる日本語の静的デモです。架空フリマの 3 商品と固定の AI 処理結果を使います。外部への通信、実際の出品や取引、ログイン、登録、決済はありません。

## ローカルで確認する

- このフォルダの `index.html` をブラウザで直接開きます。`file://` でも動く通常のスクリプトと相対パスだけを使用しています。
- HTTP で確認する場合は、このフォルダで `python3 -m http.server 8080` を実行し、ブラウザで `http://localhost:8080` を開きます。サーバーは Ctrl+C で停止します。
- パッケージのインストールやビルドは不要です。外部のフォントやライブラリを読み込みません。

架空フリマを新しいタブで開き、商品ページの「このページの URL をコピーする」を押します。元の体験版タブの「AI出品」に戻り、URL を貼って「取得」を押してください。クリップボードが使えない場合は URL 欄が選択され、手動コピーを案内します。「この商品で試す」でも URL を入力できます。

状態は 1 つの `Demo.state` に集約し、利用できれば `localStorage` に保存します。ストレージが使えない場合はメモリ上で動作し、再読み込みすると状態が失われます。`file://` のストレージやクリップボードの挙動はブラウザに依存します。フリマから戻る際は元の体験版タブを使うと、この場合も体験を継続できます。「最初からやり直す」でデモだけを初期化します。入力欄に実際の個人情報を入力しないでください。

## Cloudflare Pages に置く

このリポジトリを静的サイトとして配置します。設定値は次のとおりです。

- フレームワーク: なし
- ビルドコマンド: なし（空欄）
- ルートディレクトリ: このリポジトリのルート
- 出力ディレクトリ: `/`

`index.html`、`market/`、`assets/` を同じ階層関係で配信してください。直接アップロードでも、これらのファイルを含めれば動作します。認証情報や環境変数の設定は必要ありません。画面の切り替えは `#/products` などのハッシュを使うため、ルートのリライト設定は不要です。この作業ではデプロイしていません。

## 計算とデモの決めごと

- 手数料は `(売値 + 買い手送料) × (13.25% + 1.35%) + 0.40 USD`。円換算後に国際送料と仕入れを引き、最後に手残りを四捨五入します。既定の為替は 155 円/USD（例）。収益管理では国内送料と広告費も引きます。
- 0.36 kg の SpeedPAK の式から出る例の送料は **3,656 円**です。仕様の計算テストに指定された **3,654 円**は別の送料入力として検査し、その手残りは **2,140 円**です。通常のカードの送料 3,656 円では手残りは 2,138 円です。
- 収益管理の過去の大型フィギュアは、実績の送料 8,700 円の例です。
- 初期のダミー出品を 2 件用意し、あなたの出品とは別のレコードにしています。在庫監視では初期のカードを取り下げ、注文ではあなたの出品または残りのカメラを利用できます。デモでは 1 出品につき 1 回購入を再現でき、販売履歴をウォッチャー分析に残します。
- バッグは証明がないというデモの設定で出品を拒否します。本物と証明できるブランド品を一律に禁止する表現にはしていません。
- AI の英文は商品ごとの固定例です。テンプレートと指示は保存し、英語の結果は手で編集できます。返信案は注文の発送状態を反映します。編集した英文の日本語訳は自動更新しません。
- 「毎週」の自動出品は月曜日の設定例。実行結果は固定の例で、ブラウザのバックグラウンド処理や実際のタイマー実行はしません。
- 発送登録時の運送会社から見積もりを再計算し、実際送料は見積もり + 240 円という例を追加します。収益管理への実際送料の反映は手入力です。過去の注文の売値は、その後の値下げで変わりません。
- ガイドは完了した操作を状態から判定します。閉じてもメニューは自由に使え、再開・初期化ができます。途中でダイアログを閉じると、そのローディング処理はキャンセルされます。

## テスト

Node.js の標準機能だけを使用します。

```sh
node tests/calc.test.js
node tests/workflow.test.js
find assets/js tests -type f -name '*.js' -exec node --check {} \;
```

計算テストは手計算の式、赤字、送料、買い手送料、追加費用、URL の許可・拒否、ブランド規制の実際の拒否を検証します。静的検査は `index.html`・`market/`・`assets/` の全ファイルを読み、外部通信・外部リソース・外部リンク・禁止ブランド名・秘密情報に似た設定・画像名を検査します。SVG の名前空間 URI は外部リソース取得ではありません。ローカル HTML の参照先と `defer` も検査します。

## 未確認の点と手動確認手順

ブラウザでの見た目・実際の操作は未確認です。特に 360px 幅での横スクロールの有無、固定の注意書きと各要素の重なり、キーボード操作、色の見え方、スクリーンリーダー、`file://` での保存・コピーは、配信前に確認してください。表だけは内容を保つため枠内で横スクロールする設計です。

1. `file://` と HTTP の両方で、ガイド付き開始 → カード取得 → AI処理 → 結果確認 → 利益計算 → 出品 → ダッシュボードへ進む。
2. 在庫監視で初期カードを売り切れにし、あなたの出品が残っていることを確認。あなたの出品で購入を再現し、追跡番号の例を入れて発送する。
3. メッセージの訳と発送済みの返信案を確認して送信。ウォッチャー分析、オファー、自動出品設定、収益管理、送料管理を経てまとめへ進む。
4. バッグを取得して AI処理を行い、結果と「出品する」の両方で警告が出て、出品が増えないことを確認する。
5. 不正な URL、赤字になる条件、テンプレートの停止・再開・削除、運送会社フィルター、再読み込み・初期化を確認する。
6. 360px 幅でドロワーを開閉し、すべての画面を確認する。ダイアログの Tab 循環、Esc での閉鎖、フォーカス復帰、OS の動きを減らす設定も確認する。
