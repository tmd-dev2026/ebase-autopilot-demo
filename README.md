# eBase Autopilot 体験版 v3

商品取得、AI 処理、利益計算、出品、在庫監視、注文、返信、収益管理を体験する日本語の静的アプリです。6 商品と固定の AI 結果を使い、取引や外部 API 通信は発生しません。架空フリマは別サイトです。リンクを開いた場合だけ、ブラウザが別タブでそのサイトへ移動します。

## ローカルで確認する

- このリポジトリの `index.html` を直接開くと `file://` で利用できます。
- HTTP では、このフォルダで `python3 -m http.server 8080` を実行し、`http://localhost:8080` を開きます。停止は Ctrl+C。
- ビルド、npm パッケージ、CDN、外部フォントは不要です。

フリマを開くリンクは「はじめに」、ガイドの手順 2、不正 URL の案内にあります。商品カードの「元ページ」も、その商品の別サイトの URL を開きます。フリマの商品ページで URL をコピーし、元の体験版タブの「AI出品」に貼って取得してください。不正 URL の案内には全 6 商品の URL とコピーボタンがあり、クリップボードが使えなければ選択状態から手動コピーできます。

### 別サイトと 2 サイトで動かす

フリマの既定の公開先は `https://tmd-dev2026.github.io/ebase-market-demo/` です。変更する場合は `assets/js/config.js` の `marketUrl` を編集してください。末尾 `/` を含めます。商品 URL はこの設定と `items/<slug>.html` を組み合わせます。

両方をローカルで確認するときは、別途用意したフリマ側リポジトリで `python3 -m http.server 8081` を実行し、体験版の `marketUrl` を `http://localhost:8081/` に変更します。体験版は 8080、フリマは 8081 のタブを開きます。公開前に `marketUrl` を公開先へ戻してください。フリマのファイルをこのリポジトリへコピーする必要はありません。フリマ側を直接 `file://` で開いた商品 URL も、パス末尾が対応する `items/<slug>.html` なら取り込めます。

URL 判定はホストを見ず、パス末尾と用意された slug を検査します。`.html` なし、末尾スラッシュ、クエリ、ハッシュ、前後の空白に対応します。旧形式・未知の商品・実行可能な URL は拒否します。入力 URL を読み込みに使うことはありません。

## 次のステップの差し込み方

`assets/js/config.js` の `ctaUrl` に `https://` で始まる案内先 URL を設定すると、まとめの「次のステップ」に別タブで開くボタンが表示されます。`ctaLabel` でボタンの文言、`ctaNote` で説明文を変更できます。`ctaUrl` が空、または `https://` 以外の場合は説明文だけを表示します。カードは体験の進み具合にかかわらず表示されます。

## 操作と保存

- 通常の単品入力: 取得 → `#/ai-process/<id>` に自動遷移 → 5 段階の AI 処理 → 結果編集。
- 全自動モード: 同じ画面で取得 → AI 処理 → 価格設定。3 社を比較して手残りが最大の配送方法を適用します。出品は自動実行しません。
- 一括入力: 1 行 1 URL、最大 6 行。無効な行や 7 行目以降には行番号と理由を表示し、有効な行を順に取得します。通常モードは取得後に選択した商品を「一括AI処理」、全自動モードは各商品の価格設定まで続行します。同じ商品は重複登録しません。
- 6 商品すべて出品できます。大型フィギュアも全自動処理を完了し、価格カードに「⚠ 赤字」を表示します。赤字による停止や確認操作はありません。
- 出品前チェックは「要修正(n件)」「注意(n件)」。英語タイトルは 1〜80 文字、説明文・カテゴリ・コンディション・Item Specifics は必須です。未入力や長すぎるタイトルは編集してから出品します。「出品する」から直接送信の演出へ進みます。
- 「今日」は今回取得した商品、「昨日」は過去の AI 処理済み見本 2 件です。今月のカウンターは今回の取得件数です。実際の利用枠の制限はありません。
- 初期データは出品中 5 件、ウォッチャー合計 87、注文 5 件、メッセージ 3 件、テンプレート 2 件、過去の収益 4 件、送料 8 件。すべて例です。ウォッチャー分析は商品ごとの代表出品 6 行（未出品のバッグを含む）で、あなたの出品があれば優先します。
- 初期出品とあなたの出品は別の記録です。在庫監視では初期出品を取り下げ、別の出品で購入を再現できます。購入済みの出品は終了し、同じ出品から重複注文を作りません。
- 12 ステップのガイドは状態から進捗を判定します。初期の発送済み注文やテンプレートだけでは、今回の操作を完了扱いにしません。全メニューはガイドを閉じても使えます。
- AI の英文は固定例です。テンプレートと指示は保存され、結果は編集できます。再処理は編集内容を初期英文へ戻します。メッセージの返信案は発送状態と追跡番号を反映します。

アプリ状態は `Demo.state` に集約し、`localStorage` の v3 用キーに保存します。v1・v2 の状態は引き継ぎません。保存が使えない場合もメモリ上で動きます。再読み込み中に処理を再開することはなく、処理中だった進捗は中断と表示します。モーダルの処理は Esc または閉じる操作でキャンセルできます。

テーマ未設定時はシステムの配色を使い、ヘッダーの月／太陽ボタンでライトとダークを切り替えて保存します。「最初からやり直す」はデモ状態だけを初期化し、テーマを保持します。`file://` の保存・コピーの可否はブラウザに依存します。入力には実際の個人情報を使わないでください。

在庫監視はダッシュボードの該当カード、または出品管理の「在庫監視を見る」から開けます。最初は売り切れが 0 件なので、ガイドで開始できるようダッシュボードに再現用リンクも置きました。優先対応は仕様で具体的に列挙された 7 種を採用し、要対応→警告→情報、同じ重要度では件数の多い順です。出品エラーと仕入れ元の変化は要対応、値下げ候補は警告、残りは情報としました。発送待ちは 5 件以上が要対応、未満が警告です。リンクの `?filter=` で該当する一覧を絞り込みます。0 件のカードは表示しません。

商品カードの画像ボタンはキャプション付きの画像モーダルを開きます。商品情報の別パネルや出品直前のチェックリストは取り除きました。v2 の保存状態は移行せず、v3 の初期状態で開始します。テーマ設定は継続します。

## 計算

利益計算の送料比較は、送料が最も安い配送方法に「最安」を表示します。「手残り(例)」列と赤字表示も残しています。

手数料は `(売値 + 買い手送料) × (13.25% + 1.35%) + 0.40 USD`。手残りは、手数料を引いた額を為替で円換算して国際送料と仕入れを引き、最後に四捨五入します。既定の為替は 155 円/USD（例）。見込み利益率は円の見込み利益 ÷ 円の収入 × 100（USD 換算でも同率）です。為替または収入が 0 のとき、計算できない換算・率は「—」にします。収益管理では国内送料と広告費も引きます。

SpeedPAK の例は `round(2900 + 2100 × kg)`。0.36 kg は 3,656 円、カードの手残りは 2,138 円です。元の仕様のテスト用送料 3,654 円は別入力として検証します。大型フィギュアの赤字例は用意済みの売値 $90、仕入れ 7,500 円、4.1 kg をそのまま使い、送料 11,510 円、手残り −7,159 円です。

発送登録時の実際送料は見積もり + 240 円の例です。実際送料の収益表への反映は手入力です。注文時の売値は、その後の値下げで変わりません。自動出品の「毎週」は月曜日の設定例で、実際の定期実行はありません。
